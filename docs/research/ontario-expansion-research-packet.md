# Ontario Building Permit Expansion Research Packet for Vero Permit

## Executive summary

Ontario is now operating under the **2024 Ontario Building Code**, which is established by **O. Reg. 163/24** under the **Building Code Act, 1992**. The regulation adopts the **National Building Code of Canada 2020** by reference, except where modified by the **Ontario Amendments to the National Building Code of Canada 2020**. As of the current consolidated regulation, the Ontario amendment document date is **April 21, 2026**. The 2024 code came into force on **January 1, 2025**, and the practical transition window for use of the 2012 code ended after the grandfathering period tied to **December 31, 2024** drawings and **March 31, 2025** permit submissions. For Ontario launch planning, Vero should treat the **2024 OBC + amendment-document date** as the versioned source of truth, not just “Ontario code” in the abstract. citeturn25search1turn25search2turn25search0turn25search4turn25search11turn29search7

Ontario’s permit system is **province-set but municipality-enforced**. The province updates the Act and Code and maintains qualification/registration systems for building practitioners, but it **does not oversee municipal enforcement activities**. Municipalities generally issue building permits, appoint **Chief Building Officials** and inspectors, set permit fees, review permit applications for code and applicable-law compliance, and conduct site inspections. A key exception is that **on-site sewage systems** may be administered by boards of health or conservation authorities rather than the municipal building department. This means Ontario support in Vero cannot be province-only; it must be **province + principal authority/municipality aware**. citeturn29search0turn10search7turn10search0turn29search9turn28search5turn28search7

For small residential projects, Ontario has a recognizable baseline document set: the provincial **Application for a Permit to Construct or Demolish**, **Schedule 1: Designer Information** where applicable, scaled drawings, a site plan, and frequently project-specific submissions such as **SB-12 energy documentation**, lot grading information, plumbing/HVAC support documents, septic information, and municipal “applicable law” or zoning review materials. However, the exact submission package varies significantly by municipality. Toronto uses project-type application guides and sometimes a **Zoning Applicable Law Certificate** path; Ottawa uses structured submission requirement pages, homeowner checklists, and a **Confirmation of Commitment by Owner** for certain projects; Mississauga relies heavily on **ePlans**, an **Applicable Law Form**, and project-specific drawings/documents pages. citeturn8search0turn13view2turn15view0turn17view0turn16view3turn18search6turn18search12turn18search3turn20view1turn20view2turn20view3turn1view7

The biggest Ontario-specific SaaS risk areas for Vero are not the generic permit package steps; they are the **designer/professional responsibility layer**, **municipal applicable-law variation**, **occupancy terminology**, and **multi-unit/adjacent-unit complexity**. Ontario uses **BCIN-based designer qualification language**, embeds designer responsibility through **Schedule 1**, and uses the term **general review** when architect/engineer construction review obligations apply. Municipal forms and guides also show that detached suites, additional units, and projects with more than two units can trigger materially different code and approval analysis. Vero should therefore launch Ontario as a **document-assembly and workflow-orchestration product**, not as an automated compliance engine or professional substitute. citeturn14view0turn23search1turn23search0turn11search5turn11search11turn15view0turn19search5turn18search10

The safest Ontario rollout path is a phased one: first build a **research-verified provincial resolver and terminology layer**; then scaffold municipal overlays; then launch tightly bounded templates for **small residential additions, single detached houses, and the simplest secondary-unit cases** in selected municipalities. Projects involving **septic systems, detached suites with municipal fire-access overlays, three or more dwelling units, complex change-of-use issues, or architect/engineer/general-review triggers** should remain outside any “self-serve compliant” claim unless reviewed municipality-by-municipality and, where needed, by licensed professionals. citeturn26search0turn17view3turn19search5turn18search10turn11search1turn11search5turn29search0

## Ontario code and permit framework

### Ontario building code framework

The current Ontario building code regulation is **O. Reg. 163/24** under the **Building Code Act, 1992**. Its core structure is unusual compared with older Ontario editions: rather than reproducing a full standalone provincial code text in e-Laws, Ontario now adopts the **National Building Code of Canada 2020** by reference, as amended by a separately maintained **Ontario Amendments** document. Ontario’s public guidance explicitly says the new regulation is “one page long,” adopts NBC 2020 except where amended, and that the full-length version is no longer available on e-Laws. citeturn25search1turn25search11turn7search1turn7search8

For a software resolver, that matters a great deal. The operative code is not just “NBC 2020” and not just “O. Reg. 163/24”; it is **NBC 2020 + Ontario Amendments at a specific dated version**. As of the current 2026 consolidation, the referenced Ontario amendment document is dated **April 21, 2026**. Ontario updated that date twice in April 2026, first from **October 21, 2025** to **April 1, 2026**, then from **April 1, 2026** to **April 21, 2026**. Vero should therefore version Ontario content by **amendment-document date**, not merely by regulation number. citeturn25search1turn25search2turn25search0

The 2024 Ontario code came into force on **January 1, 2025**. Ontario’s transition rule continued the 2012 code for work where a permit had already been issued by **December 31, 2024**, or where working drawings/plans/specifications were substantially completed by **December 31, 2024** and the permit application was filed by **March 31, 2025**. Operationally, that means a 2026 Ontario template should assume the 2024 code is the live path for new work, but Vero should preserve the ability to flag **historical-file exceptions** when users import older projects or revisions. citeturn9search13turn25search4

Ontario also describes the 2024 code as a streamlining exercise that eliminated at least **1,730 technical variations** between provincial and national requirements. That is useful expansion context: Ontario is more aligned with the national model than before, but it is still not a “pure NBC 2020” jurisdiction because the Ontario Amendments document remains legally central. citeturn29search7turn25search11

For 2026-specific monitoring, two items stand out. First, the amendment-document date changed in 2026, which directly affects content versioning. Second, Ontario’s public Building Code page says **Building Code examinations shifted to the 2024 code as of March 30, 2026**, a signal that the practitioner ecosystem is now expected to work from the new code set. In parallel, the **Building Homes and Improving Transportation Infrastructure Act, 2026** amended the Building Code Act, 1992; while the small-residential SaaS implications are not fully enumerated in the search-accessible summaries, its enactment is a clear cue that Vero should maintain a legislative-monitoring function rather than treat Ontario’s framework as static. citeturn25search1turn25search7turn25search12turn25search13

### Building permit authority

In Ontario, a building permit is issued by the **body responsible for enforcing the Building Code in the area**. In most cases that is the municipal building department. Ontario’s own citizen guidance says building code enforcement and permit issuance are generally carried out by municipalities, but in the case of **on-site sewage systems**, enforcement may be handled by **boards of health** or **conservation authorities**. The provincial permit application form itself also reflects this by directing applications to a **municipality, upper-tier municipality, board of health, or conservation authority**, depending on who has the principal-authority role. citeturn29search9turn28search7turn28search5

The **Chief Building Official** and inspectors are municipal enforcement officers under the Building Code Act structure. Ontario’s regulatory-roles guidance says each municipal council must appoint a CBO and as many qualified inspectors as needed. The municipality’s role includes setting permit fees, reviewing and issuing permits, inspecting construction for compliance, and issuing stop-work or compliance orders. Ontario’s statute summary likewise reflects that municipalities and other principal authorities have CBOs and inspectors with powers and duties under the Act and Code. citeturn10search7turn10search0turn28search5

The **province’s role is different**. Ontario states that the province updates the Building Code Act and Building Code and maintains the qualification/registration system for practitioners, including building officials, certain designers, on-site sewage installers, and registered code agencies. It also says plainly that the province **does not oversee municipal enforcement activities**. This is important for Vero’s product posture: a province-wide Ontario mode can standardize terminology and baseline document categories, but it cannot promise a single enforcement workflow or a single completeness standard across municipalities. citeturn29search0turn29search3

What varies by municipality is not the existence of the Code, but the **practical approval machinery**. Municipalities differ on portals, local building by-laws, completeness screens, zoning-precheck mechanisms, imposed supporting forms, grading and tree-protection requirements, checklist structure, inspection request UX, and naming of some inspection stages. Toronto, Ottawa, and Mississauga all review for Ontario code + zoning + applicable law, but they package that work differently enough that Vero should model municipal rules as **overlays** rather than assume a single Ontario submission template will be sufficient. citeturn24search13turn18search7turn1view7turn15view2

### Professional and qualification responsibilities

Ontario’s small-residential environment has a more explicit **designer qualification vocabulary** than many BC/Vancouver-centric permit tools assume. The province qualifies and registers certain designers and firms, and assigns **BCINs** through the qualification/registration system. Ontario’s practitioner materials and BCIN datasets confirm that BCINs are a standing part of the regulated building-practitioner ecosystem, not just an optional municipal preference. citeturn23search0turn23search1turn23search15

That vocabulary appears directly in permit paperwork. **Schedule 1: Designer Information** is the standard Ontario mechanism for identifying the person who reviews and takes responsibility for design activities. The form lists design activity classes such as house, small buildings, HVAC-house, building structural, plumbing-house, and on-site sewage systems. It also states that the designer must declare either BCIN-backed qualification/registration or an exemption basis. The same form notes that it is **not required** from an Ontario architect or an Ontario professional engineer/authorized holder in the referenced licensing categories. citeturn13view2turn14view0

Municipal guides reinforce this structure. Toronto’s guides say that if drawings are prepared by a qualified designer, they must include the designer’s name, registration number, qualification ID number, signature, and statement taking responsibility for the design activities. When drawings bear a professional engineer’s seal, Toronto requires an **Assumption of Responsibility for Engineering Content** form. Mississauga’s designer qualification notice similarly says Schedule 1 registration/qualification information should appear on supporting documents. Ottawa’s submission pages for larger or more complex buildings explicitly call for **Schedule 1 with BCIN designer, architect, or engineer**, and a **Confirmation of Commitment by Owner** for certain files. citeturn16view3turn17view0turn17view4turn19search10turn18search12turn18search3

Ontario also uses the term **general review** for construction-phase professional review obligations where they apply. The Building Code Act summary identifies general review as a designer role when the code requires it, and municipal form indexes in Toronto and Mississauga contain **Commitment to General Review** type forms. The OAA and PEO joint bulletin and PEO guidance are the right primary regulator sources for this layer. They do not support any claim that a SaaS product can substitute for that function. citeturn11search7turn11search12turn11search3turn21view0turn11search5turn11search11

Architect/engineer triggers should be treated cautiously. The Ontario Association of Architects says Ontario law requires an architect for most public-use and large buildings, subject to statutory exceptions. That does **not** mean small residential work never needs an architect or engineer; it means those determinations depend on project type, size, use, structural scope, and the relevant statutory exceptions. Vero should therefore collect the right metadata and route such files to “professional review required/possible” states rather than trying to conclusively decide the issue in a province-wide template. citeturn11search1turn11search5

### Ontario small residential workflow

A typical Ontario small-residential workflow looks structurally similar across municipalities, but the details differ enough that Vero should use a **common skeleton + local overlay** architecture. The shared skeleton is: determine whether a permit is required; confirm zoning/applicable-law constraints; determine project type and basic building classification; prepare application, drawings, and municipal support forms; submit through the municipal/principal-authority channel; clear completeness/pre-screening; undergo zoning/building-code/applicable-law review; resubmit if withheld/comments arise; receive the permit; keep permit/approved drawings on site; request mandatory stage inspections; obtain occupancy approval where applicable; and close with final inspection. Toronto, Ottawa, and Mississauga all support this broad pattern. citeturn1view5turn18search7turn1view7turn5view4turn30search9turn26search7turn1view8

For a **single-family new house**, the workflow is document-heavy up front. Toronto and Mississauga both require substantial site, floor, elevation, section, and energy-efficiency documentation, and both also layer in local grading and service information. New-house files also create the clearest need for designer metadata, plumbing/HVAC associations, and potential lot-grading or tree-related municipal overlays. citeturn17view0turn16view0turn20view1turn15view0

For a **renovation or addition**, the same general path applies, but the most common decision points are whether the work affects structure, fire separation, plumbing, HVAC, egress, or energy documentation triggers. Toronto’s addition guide and Ottawa’s residential-addition checklist both show the importance of site plan + architectural details + inspection staging, while Mississauga’s addition page shows a still-structured but narrower form set compared with a brand-new dwelling. citeturn17view4turn13view4turn20view2

For an **ADU / garden suite / secondary suite**, Vero should treat Ontario as **multi-term and municipality-specific**, not as one generic “ADU” workflow. Toronto distinguishes between **secondary suites**, **garden suites**, and **laneway suites**. Ottawa distinguishes **additional dwelling units** and **coach houses**, with city-specific zoning rules allowing up to three total units on a lot in some circumstances. Mississauga uses **additional residential units**, including attached units and detached **garden suites**, and explicitly warns that buildings with more than two units can trigger additional Ontario Building Code implications. This area should therefore be a controlled template family, not a single Ontario-wide template. citeturn5view2turn5view3turn4search1turn18search10turn18search0turn18search5turn19search5turn19search13

For a **duplex or small multi-unit** or a **townhouse/small Part 9 multi-unit**, the workflow may still look permit-wise like a Part 9 “small building or house” path, but the design and review complexity rises quickly. Toronto’s fee/material language still groups single-family dwellings, semis, townhouses, and duplexes within its residential permit ecosystem, and Mississauga’s residential-use guide covers low-rise small residential projects. That said, once the project moves beyond a simple one- or two-unit dwelling, Vero should assume higher review risk for fire separation, exiting, servicing, and profession-trigger questions. citeturn5view0turn19search8turn19search5

## Inspection stages and terminology

## Vero implementation implications

### Vero implementation implications

The safest Ontario architecture for Vero is a **resolver stack with three layers**: a **provincial core**, a **municipal overlay**, and a **project-type overlay**. The provincial core should contain the Ontario permit form family, Schedule 1/2 logic, BCIN/designer concepts, normalized inspection ontology, and Ontario terminology. The municipal overlay should handle local portals, file conventions, zoning/applicable-law forms, grading/tree/local declarations, and inspection aliases. The project-type overlay should handle new house, addition, secondary-suite/internal additional-unit, detached suite, and higher-risk multi-unit variants. That structure matches the way Toronto, Ottawa, and Mississauga publish their requirements. citeturn15view0turn15view1turn18search12turn20view0turn20view1turn20view2turn20view3

For **jurisdiction slug naming**, the recommended pattern is an Ontario namespace that distinguishes province, municipality, and authority context. A practical example would be a province slug like `ca-on`, municipal overlays like `ca-on-toronto`, `ca-on-ottawa`, and `ca-on-mississauga`, and authority flags for cases such as `septic_authority=conservation_authority`. The need for that extra authority dimension is directly supported by Ontario’s principal-authority and sewage-administration structure. citeturn29search9turn28search7turn26search0

For **template resolver inputs**, Vero should collect, at minimum: municipality/AHJ; project archetype; new/addition/alteration/demolition/change-of-use status; existing and proposed dwelling-unit count; storeys; building area if known; whether the file is clearly within a simple Part 9 small-building path; whether plumbing/drains/water service/HVAC are in scope; whether the property is on municipal services or septic; whether detached-suite/fire-access conditions may apply; whether any architect/engineer is engaged; whether drawings are sealed or BCIN-based; and whether a zoning/applicable-law pre-review or other approvals are already in hand. Those fields directly mirror the published Ontario forms and municipal guides. citeturn13view2turn15view2turn17view0turn17view2turn6search3turn20view1turn20view3

For **evidence and document fields**, Vero should not use one generic “drawing set uploaded” flag. Ontario support should separately track: application form; Schedule 1; Schedule 2 if relevant; site plan; floor plans; elevations; sections; foundation information; grading plan; energy documentation; plumbing data/layout; HVAC/ventilation documents; applicable-law form or zoning-precheck artifacts; local owner/professional commitment forms; and external approvals such as conservation authority, heritage, MTO, or committee-of-adjustment decisions. That granularity is visible across Toronto, Ottawa, and Mississauga source sets. citeturn15view0turn15view1turn18search6turn18search12turn20view1turn20view2turn20view3turn1view7

For **inspection-stage mapping**, Vero should build a normalized Ontario ontology with municipal aliases rather than a strict single ladder. Suggested normalized keys are: `footing_or_excavation_ready`, `foundation_or_backfill`, `site_services`, `underground_plumbing`, `framing`, `hvac_rough_in`, `plumbing_rough_in`, `insulation_air_vapour`, `fire_separation`, `occupancy_prior_to_completion`, `hvac_final`, `plumbing_final`, and `final_completion`. Toronto, Ottawa, and Mississauga all support this ontology, but none use exactly the same words. citeturn13view3turn2view0turn30search0

For **authority package wording**, the product should speak carefully. Recommended phrasing is along the lines of: “Prepared for submission to the applicable Ontario principal authority/municipality. Applicant, owner, and designer remain responsible for verifying zoning, applicable law, Ontario Building Code compliance, and all professional obligations. Permit issuance, inspection acceptance, occupancy approval, and final sign-off remain decisions of the municipality or other principal authority.” That wording is aligned with Ontario’s allocation of provincial, municipal, CBO, and inspector roles. citeturn29search0turn10search7turn29search9

For **disclaimers**, Vero should expressly state that it does **not** issue permits, make final code determinations, conduct inspections, replace the municipality, replace the CBO or inspectors, replace architect or engineer obligations, or replace external authorities such as conservation authorities or ESA. Ontario’s public sources support every one of those limits. ESA’s own pages also make clear that most electrical work requires a separate notification/permit and inspection process through ESA, which is another reason not to imply one-stop replacement of the regulatory stack. citeturn29search0turn10search7turn26search0turn24search6turn24search12

The **launch-safe scope** for a first Ontario release should therefore be narrower than a province-wide “all small residential” claim. My recommendation is: allow document and workflow support for **single detached houses, straightforward additions, and the simplest internal secondary-unit/additional-unit files** in selected municipalities; avoid self-serve automation for **detached suites/garden suites/coach houses/laneway suites without city overlays**, **septic**, **projects with more than two units**, **files needing architect/engineer/general review**, and **occupancy-prior-to-completion packages** until those areas have municipal or professional overlays. That recommendation is an inference from the source set, not a direct legal rule, and it is made to reduce product-compliance risk. citeturn17view3turn26search0turn19search5turn11search1turn11search5turn22search10

### Risks and unknowns

The most important risk is **code versioning by reference**. Because Ontario’s live code depends on a separate amendment document with a dated version, a resolver that stores only “Ontario 2024 code” could silently go stale. Vero should build explicit version fields for *regulation number*, *amendment-document date*, and *municipal overlay last-reviewed date*. citeturn25search1turn25search11turn25search0

The second risk is **municipal completeness variance**. Toronto, Ottawa, and Mississauga all publish clear requirements, but they do so through different mechanisms and sometimes with city-specific forms or local by-law references. That means a generic Ontario document checklist will inevitably underfit some municipalities and overfit others unless local overlays are maintained. citeturn15view0turn18search8turn20view0

The third risk is **professional-scope ambiguity**. Ontario’s BCIN, Schedule 1, sealed-drawing, and general-review concepts are clear in principle but fact-specific in application. Vero can capture the facts that drive those determinations, but it should not present itself as the final decider on when an architect, engineer, or general review is legally required. citeturn14view0turn11search1turn11search5turn11search11

The fourth risk is **dwelling-unit escalation**. Municipal sources show that internal additional units, detached suites, coach houses, and “more than two units” conditions can materially change the code and process profile. Vero should treat dwelling-unit count as a first-class routing field and avoid low-risk assumptions once a file reaches the third or fourth unit. citeturn18search10turn19search5turn20view3

The fifth risk is **external-authority dependency**. Septic is the clearest official example, but applicable-law and external-approval screens also bring in conservation, heritage, transportation, or committee-of-adjustment dependencies. Those make a pure building-department-only workflow incomplete in some Ontario files. citeturn26search0turn1view7turn15view2

### Recommended phased rollout

**Phase 1 — Ontario research and documentation only.**  
Build a locked Ontario knowledge base containing the provincial framework, permit form family, terminology, and municipality-by-municipality source map. No compliance automation claims. Output should be source-linked internal documentation first. This is justified because Ontario’s framework is province-wide but operationally municipal, and because the amendment-document versioning model requires careful content governance. citeturn25search1turn29search0turn15view0turn18search8turn20view0

**Phase 2 — Ontario resolver scaffold.**  
Add jurisdiction scaffolding for `province`, `municipality`, `principal authority`, `project archetype`, `dwelling-unit count`, `service type`, and `professional involvement`. Populate normalized Ontario document families and inspection ontology, but keep municipality-specific output behind internal or pilot flags. citeturn29search9turn26search0turn13view3turn2view0

**Phase 3 — Ontario small-residential templates.**  
Launch tightly bounded public templates for **single detached house**, **small addition**, and the simplest **internal secondary-unit / additional-unit conversion** cases in municipalities with strong public guidance. Toronto, Ottawa, and Mississauga are reasonable starting candidates because they expose enough official process detail to support template creation. citeturn17view0turn17view4turn16view3turn6search3turn20view3turn1view7

**Phase 4 — Municipal-specific overlays.**  
Add city-specific packages for Toronto, Ottawa, and Mississauga that include portal wording, local file conventions, local form dependencies, zoning/applicable-law steps, inspection aliases, and detached-suite variations. This is also the phase where Toronto ZALC handling, Ottawa DIO/RCVA handling, and Mississauga ePlans pre-screen logic should become explicit in the product. citeturn15view2turn26search3turn26search0turn1view7turn20view1turn20view2turn20view3

**Phase 5 — Professional and AHJ-governed expansion.**  
Only after the earlier phases are stable should Vero expand into higher-risk Ontario files: detached suites with fire-access overlays, septic-related workflows, occupancy-prior-to-completion packages, and small multi-unit files where architect/engineer/general-review or heightened fire/life-safety analysis may apply. These should remain explicitly marked as **professional/AHJ-governed** product domains. citeturn17view3turn26search0turn22search10turn11search1turn11search5turn19search5

The practical product posture behind all five phases is straightforward: **Vero can safely organize Ontario permit documentation and staged workflows, but it should not present itself as the decision-maker on code compliance, permit issuance, inspections, professional review, or external approvals.** Ontario’s official sources consistently place those responsibilities with the municipality or other principal authority, the CBO and inspectors, and licensed professionals where required. citeturn29search0turn10search7turn29search9turn11search5turn24search6
